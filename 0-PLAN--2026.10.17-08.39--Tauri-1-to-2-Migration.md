# PLAN — core_radio: migrate the Tauri desktop app from Tauri 1 to Tauri 2

**Verify-Cmd:** none -- set at close-out triage

## Goal

`build__tauri_app/` runs on Tauri 2 (latest stable 2.x outside the 7-day release cooldown) with
only the APIs the app uses: the frameless window's minimize / maximize / close / drag controls and
the `greet` command. It builds and starts on Linux (WSLg), and the dependency updater no longer
reports a FAILED cargo step for it.

Success criteria:
- `cargo clippy --all-targets -- -D warnings` in `build__tauri_app/src-tauri` is clean.
- `npm run tauri build -- --debug --no-bundle` produces a binary; `npm run tauri dev` opens the
  frameless window, and minimize, maximize/restore, close and title-bar dragging all work.
- `index2.html`'s `invoke("greet")` still replaces the heading with "Hello, World!".
- Only the plugins and permissions the app uses are declared (none of the nine the migrator added).
- `cargo tree -i rand@0.7.3` finds nothing (the `rand` alert closes once pushed).
- `COMMON/scripts/deps-update-all-repos.sh --update ../core_radio` shows no FAILED row for
  `build__tauri_app/src-tauri`.

## Background

Why: the 2026-10-16 updater run failed the cargo step for `build__tauri_app/src-tauri`. Tauri 2
removed the `api-all` feature (`package core-radio depends on tauri with feature api-all but tauri
does not have that feature`), so the major cannot be taken without a code migration; the updater
fell back to in-range upgrades and keeps `@tauri-apps/cli` on 1.x to match (`linked` rule).

The app (`build__tauri_app/`, marked "unfinished" in commit ae27775) is small:
- `src-tauri/src/main.rs` — one `#[tauri::command] greet`, no plugins (pre-migration).
- `src/index.html:96,133-143` — `data-tauri-drag-region` title bar;
  `const { appWindow } = window.__TAURI__.window;` then `appWindow.minimize() / toggleMaximize() /
  close()`.
- `src/main.js:1`, `src/index2.html:140-144` — `const { invoke } = window.__TAURI__.tauri;`
  `invoke("greet", ...)`.
- v1 `tauri.conf.json`: `"allowlist": { "all": true, ... }`, `withGlobalTauri: true`,
  transparent frameless window, `WebView2Loader.dll` bundled as a resource, updater off.

**Current state (mid-migration, unverified).** On 2026-10-17 the official migrator ran:
`npx @tauri-apps/cli@2.12.1 migrate` in `build__tauri_app/`. Pre-migration backup:
`/tmp/claude-1000/-home-echobravo-DEV-REPOS/b1d8413b-d0db-4a0e-83f2-6989adc94e0d/scratchpad/core_radio_tauri1_backup/build__tauri_app.tar`
(session scratch — copy it somewhere durable before the session ends, or rely on git). It changed:
- `src-tauri/Cargo.toml` — `tauri = "2"` (feature `devtools`), `tauri-build = "2"`, plus **nine
  plugins** derived from `allowlist.all`: os, clipboard-manager, http, process, shell, dialog,
  notification, fs, global-shortcut.
- `src-tauri/src/main.rs` — nine `.plugin(...)` registrations.
- `src-tauri/tauri.conf.json` — v2 layout (`frontendDist: "../src"`, `app.withGlobalTauri`,
  `identifier`, `mainBinaryName`), window gained `useHttpsScheme: true`.
- `src-tauri/capabilities/migrated.json` (~75 permissions, fs/shell/http/process included) and
  `capabilities/desktop.json` (`global-shortcut:default`). `core:window:allow-toggle-maximize`
  is **missing**, so the maximize button would be denied.
- `package.json` — `@tauri-apps/cli ^2.12.3` and nine `@tauri-apps/plugin-*` dependencies;
  `package-lock.json`, `Cargo.lock` re-resolved (`tauri` 2.12.4, `tauri-build` 2.7.3).
- **Not migrated:** `src/` (still the v1 `appWindow` and `__TAURI__.tauri` globals).

Versions vs the 7-day cooldown (crates.io / npm, checked 2026-10-17): `tauri` 2.12.4 and
`tauri-build` 2.7.3 were released 2026-10-14, `@tauri-apps/cli` 2.12.3 on 2026-10-14 — younger than
7 days until 2026-10-21. `tauri` 3.0 exists only as alphas.

Security alerts (GitHub, `knowbits/core_radio`): `rand` GHSA-cq8v-f236-94qc (fix 0.8.6) came via
Tauri 1's `phf_generator 0.8`; the migrated lock holds `rand` 0.9.5 / 0.10.3 only, so it closes.
`glib` GHSA-wrw7-89jp-8q8g (`VariantStrIter` unsound, fix 0.20.0) **stays**: Tauri 2's Linux stack
pins `gtk 0.18` → `glib 0.18.5` (`cargo tree -i glib@0.18.5`: gtk 0.18.2 ← tauri 2.12.4,
tauri-runtime-wry 2.12.2). The other open alerts belong to `build__electron_app` (out of scope).

Build environment: `pkg-config --modversion webkit2gtk-4.1 gtk+-3.0 libsoup-3.0` → not found; no
Tauri version can compile here until the system packages are installed (needs `sudo`).

Pre-existing issue found: `build__tauri_app/justfile` `build-linux/windows/mac` pass
`--target linux|win32|macos`, which the Tauri CLI rejects (it expects Rust target triples), and
`test` runs `npm test` with no `test` script in `package.json`.

## Decisions

| ID | Status | Decision | Reason |
|---|---|---|---|
| D-1 | dev-decided | Migrate to Tauri 2, as its own plan in `core_radio` | Developer's instruction 2026-10-17 |
| D-2 | agent-decided | Keep the migrator's output and correct it, rather than restart from the backup | Its config/manifest conversion is right; only the plugin/permission set and `src/` need work |
| D-3 | agent-decided | Remove all nine migrator-added plugins (Rust and npm) | `src/` uses no plugin API — only core window calls and `invoke`; every unused plugin widens the attack surface (`fs:allow-remove`, `shell:allow-execute`, `http:default`) |
| D-4 | agent-decided | One capability file `capabilities/default.json`: `core:default` + window `allow-minimize`, `allow-toggle-maximize`, `allow-close`, `allow-start-dragging` | Least privilege; exactly the calls in `src/index.html` |
| D-5 | agent-decided | Keep `withGlobalTauri: true` and the global `window.__TAURI__` API (no bundler) | The app is bundler-free by design (comment in `src/index.html:113-127`) |
| D-6 | agent-decided | Versions: latest 2.x released at least 7 days before implementation; before 2026-10-21 that is `tauri` 2.12.3, `tauri-build` 2.7.2, `@tauri-apps/cli` 2.12.2 | Same cooldown the dependency updater enforces |
| D-7 | assumed | Keep `useHttpsScheme: true` | Keeps the v1 origin on Windows (`https://tauri.localhost`), so web storage survives; harmless elsewhere |
| D-8 | assumed | Keep `WebView2Loader.dll` until a Windows build proves it unnecessary | Tauri 2 links the loader statically, but no Windows build can be run here to prove it |
| D-9 | dev-decided | `glib` alert dismissed on GitHub as "tolerable risk" (alert #31, 2026-10-17); recheck note in `build__tauri_app/README.md` | Unfixable inside Tauri 2 (gtk-rs 0.18); a permanently open alert hides the actionable ones |

Status: dev-decided · agent-decided · assumed · open (open = still to resolve at review or by ask).

## Plan validation testing

- Rust side — `cargo clippy --all-targets -- -D warnings` and `cargo build` in
  `build__tauri_app/src-tauri`.
- Config/capabilities — `npm run tauri build -- --debug --no-bundle` (the build validates
  `tauri.conf.json` and every capability permission against the registered plugins).
- Frontend — manual run (`npm run tauri dev` under WSLg): minimize, maximize/restore, close,
  drag; `index2.html` greet. No automated UI tests exist in this repo.
- Supply chain — `cargo tree -i rand@0.7.3` (empty), `cargo tree -i glib` (expected 0.18.5 only),
  versions vs cooldown.
- Updater — `COMMON/scripts/deps-update-all-repos.sh --update --dry-run ../core_radio` then
  `--update ../core_radio`.
- Full regression suite: not applicable — the repo has no test suite; the checks above cover the
  whole blast radius (`build__tauri_app/` only).
