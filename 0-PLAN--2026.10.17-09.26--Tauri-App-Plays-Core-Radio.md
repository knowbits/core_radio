# PLAN — core_radio: Tauri becomes the only desktop app; Electron is removed

**Verify-Cmd:** none -- set at close-out triage

## Goal

Core Radio ships as one Tauri 2 desktop app for Windows, macOS and Linux that shows and plays the
real player page (`src/core_radio.html`), with the desktop behaviour users had in the Electron app
plus the features a desktop radio needs. Electron and everything that exists only for it are
removed from the repo.

Success criteria:
- `build__electron_app/` and every Electron reference are gone; the repo has one npm tree and one
  Rust crate, in Tauri's standard layout (`src/`, `src-tauri/`, root `package.json`).
- `just dev` opens the Core Radio player (not the Tauri starter page); every station plays over
  `https://` on Linux (WebKitGTK), Windows (WebView2) and macOS (WKWebView).
- Desktop controls (drag area, close, devtools) work in the app and are hidden when the same page
  is opened in a browser; "View source" and "Audio errors" work in the app (no `window.open`).
- No third-party requests at runtime except the stream hosts; a Content Security Policy is set
  and the page triggers zero violations.
- Single instance, remembered window position/size, system tray (show/hide, stop, quit), OS media
  controls (Media Session: media keys, "Now playing"), last station remembered.
- `just lint` and `just test-after-deps-update` (headless self-test of the app) pass offline-capable
  checks; GitHub Actions builds and lints every push and publishes installers for all three OSes on
  a version tag; installed apps update themselves from GitHub Releases.

Out of scope: OS code signing / notarization (paid certificates; first releases are unsigned,
README explains the SmartScreen/Gatekeeper prompts); app stores; Tauri mobile; song titles from
ICY metadata; Settings/About features (icons exist without handlers); autostart; station list
changes beyond `http` → `https`; `build__scrape_loaded_html_page/` (untouched — keep its
`SECTION_TO_REMOVE_*` markers intact).

## Background

This plan was rewritten on 2026-11-01 before any step ran (STATUS log empty): the developer chose
"Tauri only, remove Electron completely". The earlier version kept both apps and a shared
preparation pipeline; several of its assumptions were wrong (below).

Verified 2026-11-01 by reading code and running commands:

- Versions now: tauri 2.12.5, tauri-build 2.7.4, @tauri-apps/cli 2.12.4, wry 0.57.1; Electron
  45.0.0 (packs and plays a stream headless: `xvfb-run -a node scripts/smoke-electron.mjs --play`).
  Root `justfile` `test-after-deps-update` builds Tauri + starts it 10 s headless, and starts
  Electron headless (`scripts/smoke-electron.mjs`).
- The Tauri app shows the starter page "Welcome to Tauri!" (screenshot under `xvfb-run`):
  `frontendDist` is `../src` relative to `src-tauri/`, i.e. `build__tauri_app/src/` (starter files).
- Tauri/WebKitGTK probe (scratch app, `xvfb-run`, all stations at once): origin `tauri://localhost`,
  secure context; every `https://` station plays (`currentTime` advances) when it gets its own
  connection — WebKit opens at most 6 connections per host, so 5 of 11 NRK streams waited in the
  parallel run and played when re-run alone; a plain `http://` DR stream also plays (no
  mixed-content block on Linux); Shoelace from jsDelivr loads; **`window.open` returns `null`**, so
  the page's "View source" and "Audio errors" (`src/core_radio.html` `viewSource`,
  `displayErrors`) throw in Tauri. NRK "Sport" fails alone too (media error 2) although `curl`
  gets audio — a station-health issue, same URL as today.
- Every one of the 11 `http://` stations answers over `https://` (HTTP 200, `audio/aacp` or
  `audio/mpeg`; NRK redirects to an https CDN; SR redirects `sverigesradio.se` → `www.` → edge).
  On Windows the origin is `https://tauri.localhost` (`useHttpsScheme: true`), where WebView2
  would block or upgrade `http://` media — moving all URLs to `https://` removes the question.
- Alpine.js is not used: its `<script>` tag is inside an HTML comment (`src/core_radio.html:541-542`);
  `src/lib/alpinejs.min.3.13.3.js` is dead. (The old plan's step "does Alpine load in Electron"
  was based on a wrong premise.)
- The Electron preparation pipeline cannot be reused: its eslint step fails (ESLint 10 needs
  `eslint.config.*`; only a legacy `.eslintrc` exists), its W3C HTML/CSS validation needs the
  network on every build, and its awk comment stripping is fragile. Its only functional job is
  uncommenting the `UNCOMMENT_FOR_ELECTRON_APP` blocks (CSS `:372-385`, HTML `:497-504`,
  `:514-532`, JS `:917-937`).
- Electron-only behaviour to carry over (`build__electron_app/main.js`): frameless transparent
  window 400×450, `autoHideMenuBar`, single-instance lock (focus the existing window), drag area,
  Close and DevTools via `window.api` (preload + IPC); hardware acceleration disabled (a WSL2
  workaround). Electron package scripts used electron-packager flags electron-builder ignores
  (fixed 2026-11-01; moot once removed).
- Tauri config gaps: `transparent: true` needs `app.macOSPrivateApi: true` on macOS; window is
  800×600 (Electron: 400×450); `identifier` `com.core-radio` vs Electron `org.bleken.coreRadio`;
  three different versions (Cargo 0.1.2, tauri.conf 0.1.3, Electron 0.1.11);
  `WebView2Loader.dll` bundled as a resource — a Tauri 1 era leftover (2024-03), Tauri 2 MSVC
  builds link the loader statically; capability description still names the starter page and
  `greet`; `src/main.rs` is the template (`greet`).
- Cross-building: macOS installers cannot be built on Linux, Windows only experimentally; the repo
  has no `.github/workflows/`. GitHub repo `knowbits/core_radio` is public (free Actions minutes).
- Open security alert: npm `minimatch` < 11.0.1 (medium, dev-only). After Electron is removed only
  eslint pulls it (10.2.6); eslint uses only `new Minimatch(…).match()` / `.pattern`, which
  minimatch 11 keeps (11.0 removed `makeRe`, `regexp`, `AST`). minimatch 11.0.3 (2026-10-28) is
  outside the 7-day release cooldown from 2026-11-04.
- Dev host: WSL2 Ubuntu without WSLg display in agent shells (`xvfb-run`, `Xvfb`, ImageMagick
  `import` available); GStreamer good/bad/ugly/libav plugins installed; node 26 (mise); COMMON
  hold rules `link core_radio npm:@tauri-apps/cli cargo:tauri major` are path-independent.
