# PLAN — core_radio: make the Tauri desktop app the real Core Radio player

**Verify-Cmd:** none -- set at close-out triage

## Goal

`build__tauri_app/` shows and plays the real Core Radio page (`src/core_radio.html`) like the
Electron app does, with the same desktop-only controls (drag area, close, devtools), built from the
same single source page by the same preparation pipeline. This makes the Tauri app a candidate to
replace the Electron app (a separate, later decision).

Success criteria:
- `just start` in `build__tauri_app/` opens the Core Radio player, not the Tauri starter page.
- Every station plays in the Tauri app on Linux (WSLg), including the `http://` streams.
- Drag area, close and devtools buttons work in the Tauri app; the Electron app is unchanged.
- One preparation script serves both apps (`--target electron|tauri`); the Electron output is
  byte-identical to before for the same input.
- Alpine.js loads in both apps (no failed `./lib/alpinejs.min.3.13.3.js` request in devtools).
- `npm run tauri build -- --debug --no-bundle` and clippy stay clean.

## Background

Why: the Tauri 1 → 2 migration (`0-PLAN--2026.10.17-08.39--Tauri-1-to-2-Migration.md`) left a
working Tauri 2 shell that still serves the starter page `build__tauri_app/src/index.html`
("Welcome to Tauri!"). Its `validate` recipe pointed at
`script_prepare_static_html_for_tauri_app.sh`, which never existed in git (copied from the Electron
justfile); the recipe was removed on 2026-10-17 so `just start` / `build-*` work. A Tauri app is
roughly a tenth of the Electron app's size, uses the system web view, and would retire the Electron
dependency tree, which carries most of this repo's open Dependabot alerts (~20 Electron advisories).

How the Electron app gets the player (read 2026-10-17):
- `build__electron_app/script_prepare_static_html_for_electron_app.sh` (333 lines) reads
  `../src/core_radio.html`, uncomments the `UNCOMMENT_FOR_ELECTRON_APP_START/END` blocks (HTML and
  JS/CSS comment forms, steps 1.01-1.02), strips comments, runs prettier, validates HTML and CSS
  against the W3C web APIs (`curl`, network), lints the extracted JS with eslint, and writes
  `build__electron_app/core_radio__processed_for_electron_app.html`.
- Electron-only blocks in `src/core_radio.html`: CSS `nav ul li.dragarea { -webkit-app-region:
  drag; ... }` (`:372-385`); HTML drag area + spacer (`:497-504`), devtools button
  `#menuChromeDevTools` (`:514-522`), close button `#menuCloseElectronApp` (`:526-532`); JS handlers
  calling `window.api.openDevTools()` / `window.api.closeApp()` (`:917-937`).
- `window.api` comes from `build__electron_app/javascript_preload.js` (`contextBridge`, IPC
  `close-app`, `open-dev-tools`; handled in `main.js:222-238`).
- The page loads Shoelace from jsdelivr (CDN, `:104`, `:554`) and Alpine from
  `./lib/alpinejs.min.3.13.3.js` (`:542`, file in `src/lib/`).
- 11 station URLs are plain `http://` (e.g. `http://live-icy.dr.dk/A/A03H.mp3`).

Tauri-side facts:
- `tauri.conf.json`: `frontendDist: "../src"` (the starter page), `withGlobalTauri: true`,
  frameless transparent window, `useHttpsScheme: true` (Windows origin `https://tauri.localhost`).
- Capability `capabilities/default.json` allows only minimize / toggle-maximize / close /
  start-dragging; `tauri` has the `devtools` feature.
- Tauri ignores `-webkit-app-region: drag`; dragging needs the `data-tauri-drag-region` attribute.
- Linux web view is WebKitGTK; audio decoding goes through GStreamer (`gstreamer1.0-plugins-good`,
  `-bad`, `-libav` present on this host, not installed by `just bootstrap` yet).
- Mixed content: an `https` (Windows) or secure custom-scheme origin may block or auto-upgrade
  `http://` audio — must be proven per platform, not assumed.

## Decisions

| ID | Status | Decision | Reason |
|---|---|---|---|
| D-1 | dev-decided | Make the Tauri app play the real page, as its own plan | Developer's choice 2026-10-17 (option b) |
| D-2 | agent-decided | Generalise the existing preparation script with `--target electron|tauri` instead of a second copy | One pipeline, one set of W3C/eslint checks; no drift between the two apps |
| D-3 | agent-decided | Keep the page's existing `UNCOMMENT_FOR_ELECTRON_APP` blocks shared by both targets, renamed to `UNCOMMENT_FOR_DESKTOP_APP`; the drag area also gets `data-tauri-drag-region` (ignored by Electron) | The desktop controls are the same in both apps; only `window.api` differs |
| D-4 | agent-decided | Tauri provides the same `window.api` (`closeApp`, `openDevTools`) through a small script the preparation step injects for the tauri target, so the page JS stays identical | No Tauri-specific code paths in the shared page |
| D-5 | agent-decided | `openDevTools` = a Rust command `open_devtools` calling `WebviewWindow::open_devtools()`; `closeApp` = `getCurrentWindow().close()` (permission already granted) | Devtools can only be opened from Rust; close needs no new permission |
| D-6 | agent-decided | Prepared output goes to `build__tauri_app/dist/` (`index.html` + `lib/`), gitignored (`dist` already ignored); `frontendDist` → `../dist`; the starter `src/` is removed | Generated files stay out of git, matching the Electron output pattern |
| D-7 | open | If `http://` streams are blocked by mixed-content rules: set `useHttpsScheme: false`, move those stations to `https://` URLs where the broadcaster offers them, or both | Depends on what C.2 proves per platform and which stations have https endpoints |

Status: dev-decided · agent-decided · assumed · open (open = still to resolve at review or by ask).
